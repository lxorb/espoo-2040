# Experiments

Every number in the paper is a macro in `paper/figs/numbers.tex` or a row in a `paper/figs/*.tex` table. All of them are written by `paper/figs/make.py`, run through `paper/build.sh`. This file says where each one comes from.

Score: `(D_nothing - D) / (D_nothing - D_best)` with `sim/norms.json` (frozen at commit `d24719a`), clipped to [0, 1] unless a row says raw. Saved share: `1 - D / D_nothing` on the same seed. Delay `D`: total person-hours over 2026 to 2045.

## Rebuild

`paper/build.sh` needs only committed files: `sim/norms.json`, `data/catalogue.json`, `evidence/`, and the summaries in `paper/figs/data/`:

| File | Content | Made by |
|---|---|---|
| `runs.json` | per-seed delays, spend, builds, maintenance of all simulated and Harbor runs | `collect.py` from scratch run folders and `jobs/` |
| `rl.json` | RL strategy rows (up to `CUT` = 5280 episodes for PPO from scratch), PPO and Gumbel curves, search, `jam` ablation, unseen-seed results | `collect.py` from `runs/rl/` |
| `grpo.json` | GRPO evaluation per step (greedy plan and saving per seed) and run A strategy rows | `collect.py` from `runs/grpo/` |
| `growth.json`, `booms.json` | seed 1 area growth; growing areas of seeds 0 to 15 | `prep.py` |

When `runs/` and `jobs/` exist, `build.sh` first runs `collect.py` to refresh these summaries. Tested on a fresh `git clone` (with the pending changes to `paper/figs/` and `paper/build.sh` copied in): the build gives the same `numbers.tex`, tables and figures as the working copy, and 10 pages.

## Data split

| Split | Seeds | Use |
|---|---|---|
| train | 1000+ (BC, GRPO), 2000+ (PPO) | training only |
| validation | 0 to 15 | checkpoint choice, all headline scores |
| test | 16 to 47 | never used for training or selection |

The learned policy checkpoint was chosen on validation seeds 0 to 15 (highest mean plus worst score). Every validation number for it is therefore optimistic; the test split measures by how much (`hoGap`).

## Conflicts with README or paper

1. Most table numbers were computed on the local AMD machine, not on the Intel VMs. Across CPU types the score can differ by up to 0.008. They should be replaced by `rl/eval.py` output from an Intel VM (`evidence/test.json`).
2. Learned policy, forecast check and rule planner numbers come from scratch `drive.py`, and maintenance-forced baselines from scratch `bl2.py`. Neither script is in the repository. `rl/eval.py` now covers the same policies (`deploy`, `planner`, `reactive:2`, ...) but not `rlcheck`.
3. PPO from scratch kept training after the paper text was written. `collect.py` freezes its strategy rows and its curve at 5280 episodes (`CUT`), which gives the values the text was written with (`evoColdEps` 5280, `evoColdScore` 0.71). The live file now reaches 20640 episodes with score 0.65; commit fff88a6 holds those live values in `numbers.tex`.
4. `curves.pdf` (a) and the Gumbel numbers come from stored runs; the Gumbel training path is no longer in the code.
5. The raw run files (`runs/`, `jobs/`, `viz/data/`) are gitignored. Their small summaries are committed in `paper/figs/data/` (see Rebuild), so the figures rebuild from a fresh clone, but the summaries themselves can only be regenerated on a machine that has the raw files.
6. README said the agent lacks cash for a 120 MEUR upgrade because it buys cheap links first and keeps maintenance at level 2 ("the reference plan with maintenance 2 scores 0.52 on seed 0"). The replays do not support this: the agent with maintenance 1 loses on all five seeds (`cfMaintOneDiff`), a growing-area upgrade is unaffordable in about as many years for the agent as for the reference (`failBlockedAgent`, `failBlockedRef`), and level 2 is only `failMaintTwoShare` of the agent's spend. Forcing maintenance 2 on the reference does cost it `cfRefMaintTwoDiff`, but the effect is not symmetric. Adding one access upgrade closes only `cfAccessGapShare` of the gap, so the gap comes from the whole plan, not one choice. README is corrected.
7. The README score table used AMD numbers. On Intel the reference minus agent gaps on seeds 0 to 4 are 0.482, 0.397, 0.032, 0.056, 0.058 (mean `gapIntelMean`, 95% CI [`gapIntelLo`, `gapIntelHi`], reference wins `gapIntelWins`, sign p `gapIntelSignP`); README now shows the Intel scores from `evidence/failures.json`.
8. Exploit suite on all 16 seeds (`exploits.tex`). The reference plan is complete after year `ExploitPlanDoneYear` and its cash first turns negative in year `ExploitFirstNegative` on every seed; after that every new action is rejected, so stopping after 7 or more years gives exactly the full score (`ExploitStopSevenGap`). Debt has no floor because emergency rebuilds are always paid (mean end cash `ExploitRefDebt` MEUR; do nothing reaches debt in year `ExploitNothingFirstNegative`, end cash `ExploitNothingDebt`). The reference with maintenance 0 beats it on `ExploitMaintZeroWins` of `ExploitMaintZeroN` seeds (sign p `ExploitMaintZeroP`) but is lower on average (`ExploitMaintZeroGap`) because of a few large losses; the reference always chooses maintenance 1. No malformed input was accepted (`ExploitAcceptedBad`); the JSON does not store the number of malformed inputs tried (28 in the script). Whether the rules change is the owner's decision; README and paper conclusions are unchanged.
9. The reference checkpoint was chosen on 2026-11-14 18:26, when PPO had reached 560 episodes. A later checkpoint (800 episodes) is slightly better by the same rule (1.8482 against 1.8455), so "best" means best at that time.
10. The older `runs/rl/heldout.json` already evaluated seeds 16 to 47 after the fact. Its numbers agree with `evidence/test.json` (`hoRl` = `testRl`); it serves only as a cross-check.
11. Earlier reports gave reactive 0.566 and 5-year greedy 0.281 (old norms, maintenance 1). With the frozen norms the values are reactive with maintenance 2 `valReactiveScore` and 5-year greedy with maintenance 2 `valGreedyFiveScore`. README's reactive 0.56 still holds; any greedy number must use the new value.
12. PPO from scratch stopped at 20960 episodes; its last eight checkpoints score 0.65 to 0.76. `CUT` = 5280 stays, because the paper text was written with those values.
13. Norms. `D_nothing` is do nothing with maintenance 1. For seeds 16 to 47, `tools/norms.py` takes `D_best` as the minimum over: single-project orderings by full-run gain (6 truncations) with maintenance 1 and 2; random, greedy, 5-year greedy and reactive with maintenance 1 and 2; the current rule planner (late off and on); the current learned policy; then three rounds of local search from the best plan (rng [1, seed]). It cannot reproduce the frozen `D_best` of seeds 0 to 15 bit for bit: their pool held the deleted first planner, old deploy logs and a different random order. Recomputed for seeds 0 to 2, `D_nothing` is bit-identical, but `D_best` is 82045981 against frozen 82361722 (seed 0), 82005639 against 83619418 (seed 1) and 71955528 against 70937440 (seed 2). So the new procedure is stronger on seeds 0 and 1 and slightly weaker on seed 2, and test norms are mostly stricter than validation norms (on seed 1 the same plan scores about 2.8% lower). Validation and test scores must not be compared directly; this belongs in the paper's limitations. Because the learned policy and the rule planner are candidates for the test `D_best`, their test scores are at most 1. For seeds 2, 7 and 13 the frozen `D_best` was back-computed from a 3-decimal score; replaying that plan gives a true loss higher by 5605, 6507 and 2228 person-hours.

14. Random valid plans now score `grpoRandomVal` (8 per seed, the first 2 to 6 projects of a random permutation, maintenance drawn from 0, 1, 2: the target distribution of the format warm-up). An older paper draft quoted "random list 0.393/0.433", which used 6 projects and fixed maintenance 1 or 2.
15. The final GRPO model equals one constant plan on all `grpoSameAsConst` of 48 seeds, and its plans do not change when the growth numbers in the prompt are shuffled or zeroed (`grpoSensFinalShuffle`, `grpoSensFinalZero`; after warm-up `grpoSensWarmShuffle`, `grpoSensWarmZero`). It does not read growth.
16. GRPO run A was trained without a torch seed, so it cannot be reproduced bit for bit; `grpo/train.py` now takes `--seed`, and two seeded runs are in progress. The macros `grpoWarm`, `grpoFinal` (from the training curve, clipped scores) differ from `grpoWarmVal`, `grpoFinalVal` (from `evidence/grpo.json`, raw mean): 0.19 and 0.83 against 0.186 and 0.831.
17. Test scores (`testRlScore` and others) use the test norms. Read with item 13: they are not on the same scale as the validation scores. On the test split the learned policy's lowest seed is `testRlScoreMinSeed` (`testRlScoreMin`).

## GRPO with room to reason (branch `grpo-reasoning`, 2026-11-15)

Question: with (1) room to reason (`--think`) and (2) no project names to memorise (`--anon`), does GRPO teach a small Gemma to read the scenario instead of collapsing to one memorised plan (run A)? Run A and its numbers are untouched; all new code is in `grpo/reason.py`, `grpo/reason_eval.py`, `grpo/factorial.sh`, `grpo/phase2.sh`, `paper/figs/grpo_reason.py`.

Machine: Verda, 1x NVIDIA RTX PRO 6000 Blackwell Server Edition (96 GB), 30 vCPU, 88 GB RAM. PyTorch 2.14.0+cu130, transformers 5.20.2, peft 0.21.3, vLLM 0.33.0 (works on Blackwell; needs `VLLM_USE_FLASHINFER_SAMPLER=0` because FlashInfer JIT needs `ninja`/`nvcc`). TRL 1.18 installed but not used: own loop (vLLM rollouts with the current LoRA, HF+PEFT gradients) because dynamic sampling and the simulator pool were simpler there.

### Environment (`grpo/reason.py`)
- Same single-turn protocol as run A: the env plays 2 years with maintenance 1, the model gets budget, growth so far, the menu (id, cost, build years, nearest area) and answers `plan: id, ...; maintain: k`; the env starts projects in order when affordable (max 2 per year).
- `--anon`: per scenario, labels P01..P22 in random order; cost and build years scaled by U(0.8, 1.2) (rounded; years at least 1), RNG `[seed, 2040]`; applied in the prompt AND the simulator (`City.cat` of that instance; `sim/` unchanged). The do-nothing delay is unaffected, so the saved share is exact; the normalised score still uses `sim/norms.json` (best known plan of the UNperturbed catalogue), so anon scores are on a slightly different scale than named ones (compare saved shares across the two; this is a confound of the factorial: anon = new labels + perturbed costs).
- `--think`: `<think>...</think>` then exactly one plan line; 1024 new tokens. The prompt asks for at most 12 short lines and shows the format. No-think: 96 new tokens.
- Reward (unchanged from run A): `clip(saved_share / 0.3 - 0.05 * wrong, -0.5, 1.5)`; wrong = unknown or duplicate ids, missing/invalid `maintain`, missing `<think>` tags, more than one line after `</think>`; unreadable (no valid id) = -0.5. Nothing about the content of the reasoning enters the reward.
- Training rewards with `fast=True`, every evaluation exact. Train seeds 1000 to 1599; validation 0 to 15 (checkpoint choice); test 16 to 47 (only final and best-validation checkpoints).

### GRPO settings (all cells)
Gemma 3 1B (`unsloth/gemma-3-1b-it`), LoRA r16 alpha 32 all linear layers, bf16 base, G=8, 8 prompts per step, temperature 1.0, beta_KL=0, AdamW lr 5e-5 (run A's value; no pilot because of the 2-hour deadline), 50 steps, token-level loss normalisation, grad clip 1.0, torch seed 0. Dynamic sampling: a group whose 8 rewards are all equal is skipped and new prompts are drawn (up to 3x8 prompts per step); `skipped` in the step log. Evaluation every 5 steps on validation seeds: greedy + 4 samples (exact simulator), plus greedy answers to three edited prompts.
Deviation: the two no-think cells ran after the two think cells (the think cells used about 86 GB of GPU memory together); same settings and budget.

### Metrics (per checkpoint, `evaluate()` in `grpo/reason.py`)
- score: normalised score of the greedy plan (raw, unclipped); saved share; validity (parsed, no format error); 95% bootstrap CI over seeds (`boot`, 10,000 resamples, RNG 0, same as `make.py`).
- boom-hit: share of the truly growing areas (hidden `City.rp`, 2 or 3 per seed) whose access upgrade is in the plan; boom rank: first position of such an upgrade.
- distinct: distinct (plan, maintain) among the 16 greedy validation plans; entropy: of the 4 sampled plans per seed.
- sensitivity: share of seeds whose greedy plan changes when the growth lines are shuffled across areas (`sens_shuffle`) or set to zero (`sens_zero`).
- faithfulness (swap test): the growth numbers are reversed across areas (the fastest area gets the slowest numbers), so growing areas look flat and vice versa. Faithful = the plan changes AND it contains the access upgrade of at least one area that now looks growing but did not before. `swap_think_new`: the reasoning names such an area as growing.
- reasoning (think runs; regex, descriptive only): think length (tokens); growth recall/precision = areas named in a sentence with a growth word (grow, fast, boom, increas, rapid, high, strong, rising) vs the truly growing areas; arithmetic = traces containing an equation `a op b = c` (share) and share of such equations that are correct (within 0.5); consistency `think_in_plan` = share of areas named as growing whose access upgrade is in the plan, `plan_in_think` the reverse.
- Trace evolution: validation seeds 0 and 1 (fixed in advance), greedy, at the first, middle and last checkpoint: `evidence/grpo-reasoning/<run>/<seed>_<step>.txt`; excerpts of the main run in `grpo_trace.tex`.

### Reference points (same protocol, `grpo/reason_eval.py refs`, seeds 0 to 47, named and anon catalogue)
- growth-aware oracle list: access upgrades of the truly growing areas (hidden information), then `olari-link`, `mankkaa-link`, maintenance 1. A heuristic that uses hidden info, NOT an upper bound: it scores below run A's constant plan.
- random valid lists: 4 per seed, first 2 to 6 of a random permutation, maintenance U{0,1,2}.
- run A constant plan (`evidence/grpo.json` `const_plan`).
- zero-shot base models (1B and 4B, think and no-think, named and anon; `reason_eval.py zero`): the "before training" point.
- The rule planner as a priority list was NOT done (time).

### Results (numbers are macros; values as of 2026-11-15 in brackets)
All validation numbers: greedy, seeds 0-15, final checkpoint (step 50) unless noted. Saved share in %.

1. **Does GRPO improve the score in each cell?** Only in the two anon cells. think+anon `grpoThinkAnonScoreZero` -> `grpoThinkAnonScore` (0.02 -> 0.25, 95% CI [0.14, 0.38]; best validation 0.30 at step 40), no-think+anon `grpoNothinkAnonScoreZero` -> `grpoNothinkAnonScore` (0.13 -> 0.30). Both named cells stay at 0.05 (`grpoThinkNamedScore`, `grpoNothinkNamedScore`), 1.7% saved. In absolute terms all of these are low: random valid lists save `grpoRefRandomAnonVal` (12.1%) on the anon catalogue, run A's constant plan `grpoRefConstAnonVal` (31.1%), think+anon `grpoThinkAnonFrac` (8.2%). On the test seeds think+anon beats random lists on `grpoThinkAnonWinsRandomTest` (17/32) seeds (sign p `grpoThinkAnonSignPRandomTest` = 0.43): the score gain over the base model is real, but the plans are not yet better than random valid lists. The 1B model did not learn to plan well in 50 steps.
2. **Does think help beyond no-think at equal budget?** Not on the score (0.25 vs 0.30 on validation, CIs overlap; test 10.9% vs 9.6%). It does on the behaviour: think+anon is the only cell whose plan follows the growth lines. Shuffling them changes the plan for `grpoThinkAnonSens` (1.00) of the seeds against `grpoNothinkAnonSens` (0.00) for no-think+anon, and in the swap test think+anon upgrades a newly growing-looking area on `grpoThinkAnonSwapNew` (0.56) of seeds against the placebo `grpoThinkAnonSwapOld` (0.06); the base model was 0.12 vs 0.19 (no direction); no-think+anon 0.50 vs 0.31. n = 16 seeds, so these are indicative, not conclusive.
3. **Does anon remove the memorised-plan shortcut?** Yes, in this setting. Both named cells collapse to ONE plan for all 16 seeds (`grpoThinkNamedDistinct`, `grpoNothinkNamedDistinct` = 1), insensitive to growth (0.00), boom-hit 0.00, and 81-89% of groups have zero reward variance (`grpoThinkNamedSkipped`, `grpoNothinkNamedSkipped`) so dynamic sampling has almost nothing left to learn from. The named think model writes plausible growth text and then outputs the first three menu entries (`keha2-north, espoonvayla-mid, kivenlahti-bridge`) plus the literal `maintain: k`. Both anon cells keep 16 distinct plans and their dynamic sampling skips only 13-14% of groups. Caveat: under anon, distinct plans are partly a label artifact (the same "strategy" maps to different labels per seed); sensitivity and the swap test are the meaningful measures, and there only think+anon reads growth. The factorial also confounds labels with the +-20% cost perturbation.
4. **Does the reasoning become more faithful, or stay decorative?** Mixed. The behavioural faithfulness rises (swap test above; `grpoThinkAnonFaithfulZero` 0.12 -> `grpoThinkAnonFaithful` 0.56). The text itself gets shorter (`grpoThinkAnonThinkLenZero` 500 -> `grpoThinkAnonThinkLen` 110 tokens) and names fewer of the truly growing areas (recall 0.83 -> 0.42); no trace contains a budget computation (`grpoThinkAnonArith` 0.00) and budget statements are often wrong (e.g. a 120 MEUR upgrade called 18 MEUR). Only `grpoThinkAnonConsist` (0.15) of the areas the reasoning names as growing get their access upgrade in the plan. The reasoning is a short growth summary that steers the plan, not a plan derivation. Continuing to 100 steps (`ThinkAnonLong`) makes it worse: score 0.25 at step 100 (best 0.31 at step 75), sensitivity 0.19, swap 0.44 vs 0.31, sample entropy falling: the start of the same collapse as run A.
5. **Does it generalise to the test seeds?** Yes in level: think+anon test score `grpoThinkAnonTestScore` (0.33; validation 0.25), saved share `grpoThinkAnonTest` (10.9%), boom-hit 0.18; the best-validation checkpoint (step 40) gives 0.31 / 10.8%. No-think+anon 0.26 / 9.6% (best-validation checkpoint 0.31 / 11.5%). Named cells 0.04 / 1.2%. Test and validation norms differ (item 13 above), so compare within a split.

What did not run (2-hour deadline): 4B GRPO (main run, control, second seed), cold start (STaR or paid traces), the rule planner as a priority list, a learning-rate pilot, second training seeds, LLM labelling of traces. The zero-shot 4B point is in `grpoZeroFour*` if the job finished. Every cell is one training seed; differences between anon cells are within noise.

**Zero-shot base models** (`grpoZero<Size><Think><Anon><Split>{Score,Frac,Valid,BoomHit,Recall}`, `reason_eval.py zero`, greedy). Gemma 3 4B without any training already reaches validation 0.31 (think+anon) and 0.38 (no-think+anon), test saved share 10.4% and 11.0%, i.e. the level the 1B reaches after GRPO (think+anon 0.25 / 10.9%). Under named menus the 4B's test saved share drops to 3.4% (think) and 0.8% (no-think; it is never format-valid). The zero-shot 1B is at 0.02 to 0.13. So in this budget GRPO brings the 1B to about the zero-shot 4B level; it does not make it better than a 4x larger untrained model, nor better than random valid lists on the test seeds.

**4B think+anon GRPO** (`4b-think-anon`, run tag `FourThinkAnon`): same settings as the 1B cells but only 30 steps (deadline), LoRA r16 on the language model's linear layers only (the checkpoint also contains a vision tower), micro-batch 1. Single seed, no control, no cold start.

**Pre-registered test criterion for the 4B run** (written and committed 2026-11-15 ~04:08 UTC, before any 4B test-seed result existed; the 1B test results were already known). For each 4B think+anon training seed (0 and 1, identical settings: lr 5e-5, G=8, 8 prompts, 50 steps, same reward), choose the checkpoint with the highest validation score (seeds 0-15, greedy; ties -> later step). Criterion: this checkpoint beats random valid lists on the anon catalogue (`random-anon`, same test seeds) in saved share on test seeds 16-47, one-sided paired sign test p < 0.05. Reported for each training seed separately, plus mean and std over the two seeds of the test saved share; the final (step 50) checkpoint is reported alongside, but the criterion uses the validation-chosen one. No setting is changed after seeing results.
